# Svarah.AI — mobile app

The voice-only workspace from the website, as an Expo (React Native) app for
Android and iOS. Hold the mic and say an offer; the app shows the facts it
understood, you answer by voice, and it makes the poster, captions, voice-over,
brag video and AI video.

The app is self-contained: it does **not** talk to the FastAPI backend. It calls
the AI providers directly and uses Firebase as its backend.

| Piece | Provider |
| --- | --- |
| Speech-to-text, voice-over | Sarvam (`saaras:v4`, `bulbul:v3`) |
| Facts, validation, campaign copy, poster artwork | Agnes (`agnes-3.0-flash`, `agnes-image-2.5-flash`) |
| Brag video | Agnes directs the storyboard; the backend's own `brag_template.html` plays it in the app |
| AI video | Magic Hour (text-to-video, several keys tried in order) |
| Accounts | Firebase Authentication — Google, or a phone number confirmed by SMS |
| Profiles and offers | Cloud Firestore — `users/{uid}`, `users/{uid}/campaigns/{id}` |
| Saved posters, voice-overs, videos | Firebase Storage — `users/{uid}/campaigns/{id}/…` |

## Setup

1. Install (from `frontend/`): `npm install`
2. Copy `.env.example` to `.env` and fill it in. `.env` is git-ignored.
3. Firebase console, for the project the app should use:
   - **Project settings → Your apps → Add app → Web**, then copy the config
     values into the `EXPO_PUBLIC_FIREBASE_*` lines of `.env`.
   - **Authentication → Sign-in method →** enable **Google** and **Phone**. Copy the Google
     provider's *Web client ID* into `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`.
   - **Project settings → Your apps → Android** (`ai.svarah.app`): add the SHA-1 of every
     keystore the app is signed with, or Google sign-in fails with `DEVELOPER_ERROR`.
     `android/app/debug.keystore` (used by both debug and release builds here) is already
     registered for `svarah-ai-42006`.
   - **Firestore Database →** create it, then paste `firebase/firestore.rules`
     into the Rules tab and publish.
   - **Storage →** create the bucket, then paste `firebase/storage.rules` and
     publish. Storage is optional: without it, generated media is kept by its
     provider link (which expires) instead of a permanent copy.

   With the Firebase CLI the rules can be deployed instead:
   `cd firebase && npx firebase-tools deploy --only firestore:rules,storage --project <project-id>`
4. Run: build it in Android Studio (below). Google sign-in and the WebView are native
   modules, so Expo Go cannot run the app any more. `npm run mobile:web` still opens the
   browser build (Google sign-in only; no phone sign-in or brag video there).

## Building an APK in Android Studio

The native project is in `android/` (generated by `npx expo prebuild --platform android`;
git-ignored, so regenerate it after changing `app.json` or adding a native package).
Regenerating wipes the folder, so never keep hand edits in it.

1. Fill in `.env` first — its values are compiled into the APK when it is built.
2. Android Studio → **Open** → pick the `android` folder and let Gradle sync. Android Studio
   installs the SDK, and offers the NDK and CMake the first time they are needed.
3. **Build → Generate App Bundles or APKs → Generate APKs** for a debug APK (it needs the Metro
   server, `npm run mobile`, to load its code), or from a terminal in `android/`:
   `gradlew.bat assembleRelease` for a standalone APK at
   `android/app/build/outputs/apk/release/app-release.apk`.

The release build is signed with the debug keystore, which is fine for installing on your own
phone but not for the Play Store. A full build compiles four CPU architectures; to save
time, build only your phone's with `gradlew.bat assembleRelease -PreactNativeArchitectures=arm64-v8a`.

## Keys live in the app

Every `EXPO_PUBLIC_*` value is compiled into the app bundle, so anyone with the
installed app can extract the Agnes, Sarvam and Magic Hour keys. That is fine
for a demo build on your own devices. Before publishing to a store, move the
provider calls behind a server (for example Firebase Cloud Functions) and rotate
the keys.

## What differs from the website

- No live transcript while speaking: the clip is transcribed when you release.
- The poster is composed on the device (artwork + the locked facts set on top).
- The brag video uses the same Brag Director prompt and the same template as the website,
  but plays live in the app instead of being encoded to an MP4 (a phone has no headless
  browser or FFmpeg), so it cannot be shared as a file and has no music bed. After changing
  `backend/app/services/brag_template.html`, run `node scripts/sync-brag-template.js`.
- The "Reel" is an animated reel that plays in the app, not a video file. The AI video
  from Magic Hour is a real file.
- The number check is deterministic on-device: every number in every caption
  must be a number from the locked offer.
- Publishing is the system share sheet; there is no Windsor connector.
- Browser builds cannot reach the AI providers if they refuse cross-origin
  requests; use a phone for the full flow.

## Layout

```
src/app/            routes — landing, login, signup, (app)/workspace|history|settings
src/lib/            config, facts engine, pipeline, package runner, Firebase, providers/, brag/
src/ui/             mic dock, poster, players, campaign bubble, shared kit
firebase/           Firestore and Storage security rules
```

`npx tsc --noEmit` and `npx expo lint` before shipping a change.
